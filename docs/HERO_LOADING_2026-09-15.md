# Стабильная загрузка Hero — 2026-09-15

## Аудит и план до изменения интерфейса

Прямой запрос: «При загрузке отображается другой шрифт, потом меняется на настоящий, и скачут фотографии, проверь Хиро блок и исправь». Исследованы globals.css, layout.tsx, page.tsx, site-images.ts, сборка Vite/Vinext, действующие проверки и прежнее решение FONT_LOADING_2026-09-13. Источник внешнего вида — опубликованный Hero: пять строк, Oranienbaum / Ysabeau Office / PT Mono, исходный портрет и 63 фотографии коллажа. Новых визуальных источников, компонентов, токенов, анимаций или библиотеки интерфейса не требуется.

Регрессия возникла при переходе на текущие гарнитуры: все 12 объявлений снова используют font-display:swap и отдельные WOFF2-запросы. Два preload не включают курсив и латиницу. В production-сборке c1ba6f0 при искусственной задержке WOFF2 на 1800 мс запасной шрифт виден около 1,75 с на 375 px. Высота заголовка уменьшается с 223,27 до 188,59 px; портрет перемещается с y=413,27 на 378,59 px (−34,68 px). Сумма layout-shift за проверку — 0,01482. На 1440 px меняется ширина заголовка; сумма сдвигов — 0,00281. Данные: artifacts/hero-loading-2026-09-15/baseline.json. Это локальные замеры с заданной задержкой, не полевые метрики посетителей.

1. Включить восемь используемых статических файлов шрифтов (400: Oranienbaum, Ysabeau normal/italic, PT Mono; кириллица и латиница) в основной CSS через Vite `?inline`, с `font-display:block`. Сохранить исходные байты, лицензии, размеры и роли. Неиспользуемые 500/600 остаются резервными файлами.
2. Удалить прежние сетевые preload. Первоначальный план доставки только с CSS уточнён по замеру: предварительно декодировать те же встроенные data URL через font-preload в head. Это не создаёт отдельных сетевых запросов. Не скрывать страницу с помощью JS и не добавлять загрузочный экран.
3. Проверить резервирование геометрии портрета и коллажа при задержке и ошибке изображений; при необходимости закрепить исходное соотношение сторон. Не менять фотографии, сетку, кадрирование и высоту секции ради маскировки проблемы.
4. Проверять с первого отображённого кадра, а не только после document.fonts.ready: готовность используемых шрифтов, координаты заголовка/портрета/плиток, layout-shift, отсутствие отдельных font-запросов. Холодная загрузка и reload, задержанный CSS, задержанные/недоступные фото, no-JS, семь ширин и увеличение текста 200%.
5. Выполнить TypeScript, соответствующие HTTP-проверки и Sites production build; опубликовать в существующих Sites-проекте и GitHub main, подтвердить результат на evgenychef.com. Домен и аудитория прежние; сохраняются удаления FAQ, цен и гостевых чисел, а также отдельный коммит соседней задачи 5dbe60d с удалением времени/места, подписи видео, примера меню и контактного заголовка.

Технические источники: [Vite — explicit inline](https://vite.dev/guide/assets.html#explicit-inline-handling), [MDN — font-display](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display). Один `block` при отдельном медленном запросе не устраняет подмену после периода блокировки; встроенные данные убирают этот сетевой этап. Цена решения — больший CSS, кэшируемый вместе со шрифтами.

## Результаты

После встроенных шрифтов проверка задержанных фото выявила независимый сдвиг на 0,58 px: 320px-вариант портрета округляет высоту, а стандартное `auto` соотношение сторон меняется с HTML 576/1280 на фактические размеры после декодирования. Для изображения закреплено исходное aspect-ratio:576/1280 с object-fit:cover; контейнер и прежнее смещение −21% сохранены.

При высокой нагрузке одного inline CSS оказалось недостаточно: декодирование всё ещё завершалось после первого layout, и пока текст скрыт правилом block, видимое место для портрета успевало измениться. Предварительная загрузка тех же восьми data URL устраняет этот промежуток. Используется серверный [ReactDOM preload](https://react.dev/reference/react-dom/preload): он создаёт ровно восемь подсказок в head и не дублирует их обычными JSX link. JS-ожидание, скрытие контента и новая анимация не добавляются.

Итоговые 26 сценариев qa-hero-loading.mjs прошли: cold/reload на 1440/1280/1024/768/430/390/375 px, CSS с задержкой 3500 мс (desktop/mobile), WOFF2 с задержкой 3500 мс (реальных запросов нет), фото с задержкой 1800 мс (desktop/mobile), ошибка всех фото и успешная перезагрузка, no-JS на desktop/mobile, 200% текста на desktop/mobile и DPR3 на 390 px. Во всех сценариях с покадровым измерением: 0 кадров с неготовыми используемыми шрифтами после FCP, 0 px изменения геометрии Hero, сумма layout-shift=0. Все 63 фото коллажа и портрет декодируются; в сценарии ошибки место сохраняется, после reload загружаются все 64. Переполнения страницы и наложения текста на портрет нет. Это измерения заданных браузерных сценариев, не обещание метрик для любого устройства.

Результаты и снимки: artifacts/hero-loading-2026-09-15/loading-report.json. Ранний scripts/qa-font-loading.mjs направлен на эту проверку: прежний тест ошибочно проверял стабильность только после загрузки шрифтов и пропускал саму подмену.

Итоговый CSS index.a2wUfntM.css: 137121 Б, gzip 91853 Б, восемь data URL. Исходные 85800 Б WOFF2 побайтно совпадают в public/fonts, app/fonts, CSS и preload. HTML: 328110 Б, gzip 187070 Б; headers 531 Б, больших font Link-заголовков нет. Проверка: delivery-report.json. Доставка увеличивает HTML/CSS, но устраняет дополнительную сетевую фазу и гонку декодирования.

Sites production build, TypeScript и ESLint изменённых исходников прошли. Пять HTTP-тестов прошли на исходном preview 3004. На vinext start:3005 пройдены четыре относящиеся к HTML/ссылкам/изображениям проверки; дополнительный тест video Range получает 200 вместо 206 из-за стандартного Node static server.
