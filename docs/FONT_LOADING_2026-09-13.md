# Смена шрифта при обновлении — 2026-09-13

## Аудит и план до кода

Пользователь сообщает: «При обновлении страницы сначала идёт один шрифт потом другой». В app/globals.css два локальных Caveat используют font-display:swap; после загрузки CSS браузер делает ещё два запроса и подменяет запасной шрифт. Кириллица — 77 224 Б, латиница — 74 572 Б. Это существующая утверждённая гарнитура, а не два разных варианта сайта.

Проверены app/layout.tsx, page.tsx, globals.css, компоненты пересчёта геометрии, конфигурация Vite, актуальные разделы DESIGN_SYSTEM, DESIGN_REFERENCE_MAP, IMPLEMENTATION_PLAN, FONT_PAIRING, APPROVED_COPY, существующие HTTP/visual проверки и локальные референсы. Структура страницы, контент, изображения, палитра, адаптивные правила и состояния уже утверждены.

1. Шаблонных элементов в затрагиваемой загрузке типографики нет; визуальная переработка не требуется.
2. Источник — прямое сообщение пользователя, возвращённый Caveat и существующий «План вечера».
3. Все компоненты, размеры, переносы, фото, тексты и взаимодействия сохраняются.
4. Изменить только font-display и доставку двух существующих WOFF2: копии в app/fonts, явное inline-включение через Vite CSS url(...?inline). Оригиналы public/fonts сохраняются. Двоичные данные должны совпадать побайтно.
5. Новые компоненты, UI-библиотеки и JS-блокировка страницы не нужны. Инлайнинг устраняет независимый сетевой этап, а block — короткую подмену при декодировании.
6. Проверить холодную загрузку, reload, медленную загрузку CSS, отсутствие отдельных font-запросов, работу без JS, прежний вид на 1440/1280/1024/768/430/390/375 px, HTTP/медиа-состояния, lint/typecheck и production build. Публикация разрешена текущим AGENTS.md.

Технические источники: [Vite asset inlining](https://vite.dev/guide/assets.html#explicit-inline-handling), [font-display](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display). Только preload+block не выбран: отдельный медленный запрос может пережить период block и снова показать fallback. Цена инлайнинга — около 202 КБ base64 до HTTP-сжатия в CSS; исходные необходимые 152 КБ шрифтов теперь передаются в том же ответе. CSS кэшируется вместе с шрифтами.

## Проверка

Проверка завершена на локальном Chrome. Производственный CSS index.OTkug1Co.css: 219 055 Б, gzip 157 492 Б, ровно два font data URL, без внешних font URL. Декодированные данные побайтно совпадают с исходными WOFF2. Сборка через Sites build-site прошла; TypeScript и ESLint исходников прошли. Общий npm run lint обнаружил три прежние ошибки require() только в неотслеживаемом design/generated/private-dinner-home-2026-09-11/finalize-foreground-mask.cjs; после исключения именно этого постороннего скрипта ESLint прошёл. Файл не изменялся.

Восемь сценариев cold/reload: desktop1440, mobile390, mobile с задержкой CSS1500мс, mobile без JavaScript. Отдельных сетевых font-запросов — 0. Caveat загружен до FCP; после первого показа текста не меняются размеры Hero. Первые внутренние замеры до paint иногда используют ещё не декодированный шрифт, но block предотвращает показ этих глифов. Проверка оценивает кадры после FCP, а не ошибочно приравнивает внутреннюю раскладку к показанному кадру. Подробности и снимки: artifacts/font-loading-2026-09-13/font-loading-report.json.

Существующий visual-qa прошёл 1440,1280,1024,768,430,390,375px. Все семь Hero и полные страницы просмотрены: прежний Caveat, пять строк Hero, прежняя композиция, без переполнения и обрезанного текста. Изображения загружаются; ссылки/клавиатурный фокус, видео, ручное управление/reduced motion и восстановление после ошибки прошли. Форм и отдельных empty-состояний нет. Пять существующих HTTP-тестов прошли. Отчёт: artifacts/font-loading-2026-09-13/qa-report.json.
