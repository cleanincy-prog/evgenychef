# Исправления после QA и видео без управления — 2026-09-15

## Запрос и исходное состояние

Пользователь: «Исправь все баги которые ты нашел, только с видео, нужно вообще убрать стоп, перемотку и т.д., оно должно просто воспроизводится».

Проверенный отчёт: `artifacts/qa-live-audit-2026-09-15/REPORT.md`. На публичном сайте MP4 возвращал полный ответ 200 на Range, WebP имели `application/octet-stream`, а DNS для www отсутствовал. Видео имело нативную панель управления. Последняя редакция текста сайта находится в commit `24330b1`; её сохраняем.

## Аудит и план до изменения интерфейса

- Визуальная опора — действующие film-stage, вертикальный кадр, постер и адаптивные размеры. Единственное изменение обычного интерфейса: удаление всей панели плеера по прямому запросу. Новые цвета, шрифты, кнопки и декоративные элементы не нужны.
- Видео без звука, inline, с повторением. Запуск в прежней согласованной позиции прокрутки; вне экрана и в скрытой вкладке приостановка для экономии ресурсов. Учитывается системное уменьшение движения. Повтор загрузки доступен только при сетевой ошибке, как в действующем оформлении.
- Корректный MIME для WebP в статических заголовках и Worker; маршрут `/media/*` должен попадать в Worker, чтобы существующая поддержка Range действительно работала. Проверка обязательна на публичном сайте после выпуска.
- Для www — отдельное постоянное перенаправление Cloudflare на HTTPS основного домена с сохранением пути и query. Существующие apex DNS и Sites-проект не меняются.
- Проверки: семь ширин 1440/1280/1024/768/430/390/375; реальное воспроизведение и повтор, отсутствие панели, выход из кадра, ошибка/повтор, reduced motion; Chrome и Firefox; TypeScript, lint, HTTP-проверки, сборка; затем публичные MIME/Range/редирект.

## Результат

- Панель и фокус видео удалены; отключены Picture-in-Picture и remote playback, касание не управляет роликом. Ошибки единственного MP4 теперь обрабатываются непосредственно на video: ранний отказ вложенного source мог произойти до подключения React и оставить только постер.
- Cloudflare: правило `e69e7e4aa28246118a9f9452fd34c19c`, DNS www `83a1d41287d282ed26c1e59c05b673b8`. Проверен HTTPS 301 с сохранением `/robots.txt?qa=redirect&value=a%20b`. Настройка сохранена в `artifacts/qa-fixes-controls-2026-09-15/www-configuration.json`.
- Локально проверены семь ширин, Chrome/Firefox, воспроизведение, касание кадра, повтор, пауза вне кадра, reduced motion и ошибка/восстановление. При искусственной задержке CSS 3.5 секунды на 375 и 1440 px: 0 кадров подмены шрифта, 0 сдвигов Hero.
- TypeScript, ESLint изменённых файлов, пять HTTP-тестов и Sites-сборка проходят. Общий `npm run lint` выявляет три прежние ошибки CommonJS в незатронутом `design/generated/private-dinner-home-2026-09-11/finalize-foreground-mask.cjs` и прежнее предупреждение img в menu-book.tsx.
- Дополнительно исправлен suffix Range: asset-сервер Vite понимал `bytes=-1024` как первые 1025 байт. Worker теперь сам вычисляет и возвращает последние 1024 байта. Проверяются начало, середина и конец файла, включая точное сравнение байтов с исходником.

## Проверка первого выпуска и уточнение реализации

Версия 84 успешно опубликована, панель удалена. Однако Sites оставил прежний MIME и ответ 200 на Range: настройки `_headers` и `assets.run_worker_first` из wrangler-сборки этим хостингом не применяются. Проверка публичного сервера выявила расхождение с локальной средой.

В итоговой сборке исходные файлы без изменения байтов переносятся из `dist/client/media` в `dist/client/_site-media`. Публичные адреса `/media/...` сохраняются и теперь попадают в Worker, который читает тот же файл через ASSETS, выставляет MIME и обрабатывает Range. Двойного сетевого запроса со стороны браузера нет. Неиспользуемый `_headers` удалён; обычный неизменяемый кеш vinext для файлов с хешами генерируется как прежде. В dev остаются исходные public/media и прежний порт.
